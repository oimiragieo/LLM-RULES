## Memory Pruning Strategy: Line-Count Truncation is SEMANTICALLY UNSAFE (2026-03-10)

**Source:** Gemini 2.5 + Codex 0.106.0 (independent, both reached same conclusion)

Raw line-count tail-truncation (e.g., `tail -200`) of multi-agent memory files causes:

1. **Foundational Amnesia** — `decisions.md` oldest entries (architecture, security model, banned libs) are pruned FIRST. New agents violate foundational invariants silently.
2. **Anti-Pattern Regrowth** — `learnings.md` "scar tissue" (what didn't work) is old → pruned first → agents repeat the same failures.
3. **Semantic Fragmentation** — decisions split across lines 50/400/600; pruning breaks the causal chain, leaving conclusions without rationale or rationale without the decision they justify.

**CORRECT approach:** Archive by SIZE THRESHOLD (not line count). The committed fix (REFLECTION_LOG_MAX_BYTES: 500KB→50KB) is correct. Line-count truncation should NEVER be used on memory files.

**PROACTIVE GUARD:** Pin an "Invariants" section at top of `decisions.md` and `learnings.md` that is ALWAYS excluded from any future pruning logic.

**ADR reference:** See ADR-120 (to be written) — Memory Bloat Prevention.
