## Key Findings from Research

### Core Responsibilities (from AWS, Mad Devs, Maruti Techlabs)

1. **Improve code structure** without changing functionality
2. **Enhance readability** and understanding
3. **Reduce technical debt** and code smells
4. **Eliminate redundancy** and duplication
5. **Maintain external behavior** while improving internal structure

### Common Techniques (from freeCodeCamp, Codacy)

1. Extract methods/functions
2. Rename variables for clarity
3. Simplify conditionals (avoid nested ternaries)
4. Reduce function size
5. Apply SOLID principles
6. DRY (Don't Repeat Yourself)
7. KISS (Keep It Simple, Stupid)

### When to Simplify (from StackExchange, Graphite)

1. When code becomes overcomplicated during development
2. After adding new features that increased complexity
3. When preparing for code review
4. When onboarding new developers
5. During maintenance cycles
6. When code smells are detected

## Disambiguation Rules

**code-simplifier vs code-reviewer:**
- code-reviewer: Checks for bugs, security, compliance, standards adherence
- code-simplifier: Improves clarity, reduces complexity, maintains functionality

**code-simplifier vs developer:**
- developer: Implements new features, fixes bugs, adds functionality
- code-simplifier: Refines existing code without changing behavior

**code-simplifier vs architect:**
- architect: Designs system architecture, makes high-level decisions
- code-simplifier: Improves implementation details and code structure
